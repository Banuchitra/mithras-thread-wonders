The per-unit loop

Every unit (U1–U6) goes round this loop once. Watch the dot: one trip round is one PR.

Feature explorer

The five Claude Code building blocks this project uses. Click each one.

CLAUDE.md: the project's standing instructions

Claude loads it automatically at the start of every session, so it's where the rules go: $0 only, no AWS yet, INR prices, tests first, follow AIDLC gates. Memory (~/.claude/…/memory) stores facts about you across projects.

Rule of thumb: if you've corrected Claude twice about the same thing, add it to CLAUDE.md.

Plan mode: think before touching files

Press Shift+Tab to cycle into plan mode. Claude can read and ask questions but can't edit. It writes a plan, and you approve or change it. That's how this project started.

Use it at the start of every unit. Skip it only for tiny edits.

Custom commands and skills: reusable prompts

Markdown files in .claude/commands/ become slash commands. This repo has /aidlc-inception, /new-unit, /unit-review and /learn-note, so each AIDLC step is one consistent command instead of a prompt you retype.

Skills are the bigger version: a folder with instructions plus scripts, which Claude loads when relevant.

Hooks: guarantees, not suggestions

A hook is a shell command the harness runs on an event, e.g. PostToolUse after every file edit. CLAUDE.md asks Claude to lint; a hook makes it happen, every time.

Added in U1, once there's a linter: the hook runs ESLint + type-check on edited files and feeds errors back to Claude.

Subagents: focused helpers with their own context

Defined in .claude/agents/*.md. Each one has its own instructions and starts with a clean context, so a reviewer isn't biased by the reasoning that wrote the code.

This repo has reviewer (correctness + conventions), a11y-auditor (accessibility) and content-checker (product data + INR prices).

How it's used in this repo

CLAUDE.md                       ← standing rules
.claude/
├── settings.json               ← hooks (added in U1)
├── commands/
│   ├── aidlc-inception.md      ← /aidlc-inception
│   ├── new-unit.md             ← /new-unit U3
│   ├── unit-review.md          ← /unit-review
│   └── learn-note.md           ← /learn-note
└── agents/
    ├── reviewer.md
    ├── a11y-auditor.md
    └── content-checker.md
Context is the scarce resource. Long sessions get summarised. Start a fresh session per unit, and let the aidlc/ files carry the context forward.

Quiz yourself

CLAUDE.md says "run lint after edits". Why also add a hook?

CLAUDE.md is guidance the model usually follows. A hook is run by the harness every time, so it's deterministic. Use hooks for anything that must always happen.

Why review with a subagent instead of asking the same session "is this good?"

The writing session is anchored on its own reasoning. A subagent starts with fresh context and only the code, so it catches more.

When should you NOT use plan mode?

For small, obvious changes like a typo or a one-line tweak. Planning has a cost, so spend it where the decisions are.
